# Power BI dashboard workspace

Git-tracked `.pbip` (Power BI Project) template that assessment 1 (dashboard mock-up) and assessment 3 (Task 5 - Power BI Dashboard) both build their own report content on top of. Design rationale, the full sync mechanism, and the test protocol live in [docs/features/06-powerbi-dashboard-setup.md](../docs/features/06-powerbi-dashboard-setup.md) - this file is the short "how do I open it and start working" version.

## Prerequisites

- Power BI Desktop, Windows-only - it cannot run inside this repo's Linux/Docker sandbox. If you're on WSL, this repo's Linux side and Power BI Desktop's Windows side share the same machine, reachable from WSL as `/mnt/c/...`.
- `POWERBI_WINDOWS_DIR` set in your local `.env` - the Windows-side path Power BI Desktop actually opens the project from (see `.env.sample`).

## Everyday workflow

The project already exists, git-tracked under this folder (see **What's in the template**) - these wrap `scripts/utils/powerbi-sync.py`:

```bash
# 1. get the latest template onto your Windows side, then open it in Power BI Desktop
./scripts/05-powerbi-sync.sh push
#    open: $POWERBI_WINDOWS_DIR\reconciliation-dashboard-user-created.pbip

# 2. after editing + saving in Power BI Desktop, capture the changes back into git
./scripts/05-powerbi-sync.sh pull
git status powerbi/

# 3. sanity-check both copies still match the last sync, without touching either
./scripts/05-powerbi-sync.sh verify
```

`push`/`pull` refuse to overwrite an un-synced change on the other side rather than guessing which one wins - if either fails with "both sides changed", resolve the conflicting file manually before retrying (see [sync script design](../docs/features/06-powerbi-dashboard-setup.md#sync-script-design)).

If `scaffold` ever reports the project missing (e.g. a from-scratch machine with `$POWERBI_WINDOWS_DIR` pointed somewhere empty), it prints a bootstrap procedure instead of generating anything - per [Revisions 06.01.R02](../docs/features/06-powerbi-dashboard-setup.md#revisions), a scripted seed generator was tried and reverted after it caused two separate Power BI Desktop failures; `report.json`/PBIR is explicitly [documented by Microsoft](https://learn.microsoft.com/en-us/power-bi/developer/projects/projects-report) as not safe to hand-author outside Desktop during preview, so a human creates Report and SemanticModel together, once, in Desktop.

## What's in the template

```
reconciliation-dashboard-template/                        # repo folder name - stable regardless of what's inside
├── reconciliation-dashboard-user-created.pbip             # Desktop-assigned name, kept as-is (see 06.01.R03)
├── reconciliation-dashboard-user-created.Report/           # pages, visuals (PBIR JSON)
├── reconciliation-dashboard-user-created.SemanticModel/    # tables, measures (TMDL)
└── sample-data/reconciliation-summary.csv                  # demo fixture, not live data
```

Built by a human directly in Power BI Desktop, then `pull`ed in - not generated by any script (see [Revisions 06.01.R01-R03](../docs/features/06-powerbi-dashboard-setup.md#revisions) for why). Its files still carry Desktop's own assigned name rather than `reconciliation-dashboard-template.*` - renaming a PBIR/TMDL object is a Desktop-only operation with its own reference-breaking risk, so it wasn't attempted from outside Desktop; the repo folder path is the stable name to depend on.

The semantic model's one table is wired to the sample CSV, not to live postgres/Spark data - per the feature's [Scope](../docs/features/06-powerbi-dashboard-setup.md#scope), that wiring is additive work for whichever assessment builds on this template.

## Adding your own content

Any edit made and saved in Power BI Desktop, or any direct text edit to the git-tracked files, is captured the same way - edit, then `pull`. `.SemanticModel` TMDL is documented and fully supported for external editing. `.Report`/PBIR is preview-only and not guaranteed safe to hand-author *from nothing* - but *extending* an already-valid report (e.g. adding one new visual, modeled on a visual already in the project) has been proven to round-trip cleanly; see [Test Cases](../docs/features/06-powerbi-dashboard-setup.md#test-cases) 06.TC.09/06.TC.14-18 for what's actually been exercised, one way or the other, before you rely on either path.
